# GA debuggability contract (#698)

Contract version: **1** (2026-11-15). Parent initiative: #683 (GA-15).

This document is the human half of the GA release gate for cross-mode
diagnostics, error contracts and test helpers. The machine-readable half is
[`tests/v2/ga/matrix.yaml`](https://github.com/nims-mdpf/rdetoolkit/blob/develop/v2/tests/v2/ga/matrix.yaml);
`tests/v2/ga/test_diagnostics_matrix.py` fails when the two drift apart,
when a cell is missing, or when a referenced test id does not exist.

## Scope

| Axis | Values |
|------|--------|
| Entry | `flow` — a v2 flow through `FlowTarget`; `callback` — a v1 dataset callback through `LegacyCallbackTarget`, the path `workflows.run(custom_dataset_function=...)` takes |
| Mode | `invoice`, `excelinvoice`, `multidatatile`, `rdeformat`, `smarttable` |
| Input | the committed contract input of each mode (`tests/v2/contract/fixtures/inputs`), materialized as `<root>/data` |

The GA cells run in process through the unified `Runner`, so a failure shows
the Python assertion. The public subprocess entry
(`workflows.run(custom_dataset_function=...)`, its exit code and its CWD
behavior) is covered by the existing `TC-UM-*-CB-ENTRY-*` cells, which the
matrix references.

## Independent oracles

A GA cell never derives its expectation from a v2 run:

- **v1 behavior** — tile/callback counts, output trees, raw digests, invoices,
  artifact digests and `job.failed` text come from the frozen v1 observations
  in `tests/v2/contract/fixtures/expected/v1/**` (generated from v1, never
  regenerated by this gate).
- **Source lines** — the expected diagnostic location is read from the source
  text of the raising function (`inspect.getsourcelines`), not from the
  sidecar.
- **Codes** — catalog codes (3001, 3002, 3005, 4001, 4002) come from
  `ERROR_CATALOG` and the contracted translation table
  (`tests/v2/contract/flow_error_table.py`); a `StructuredError` keeps the
  user's `ecode`/`emsg`.

## Outcomes

Each outcome is a row of `matrix.yaml`; every entry × mode cell of it is
either covered by named tests or excluded with a specific rationale.

| Outcome | What is asserted | Not applicable |
|---------|------------------|----------------|
| `success` | frozen v1 tree / raw / invoices / artifact digests, tile and callback count, no `job.failed`, no diagnostics sidecar, `report explain` fabricates no cause | — |
| `invalid_source_invoice` | the #647 timing of the contracted `valerr` row (`tests/v2/contract/flow_error_table.py`): a flow on invoice / MultiDataTile / RDEFormat fails 4001 at `pre_validate` on `invoice/invoice.json` with zero iterations and no user call; a v1 callback on those modes runs every tile and fails 4001 at `post_validate` on `invoice/invoice.json`, the tiles kept as completed (#685); ExcelInvoice / SmartTable fail at `tile_prepare` (3001 / 1) before user code | — |
| `structured_error` | known `StructuredError` `ecode`/`emsg` verbatim in report, `job.failed` (frozen v1 text) and sidecar; fail_fast stops at tile 0; frozen v1 tree and raw copies; phase `node_execution` at the raise line; `report explain` | — |
| `plain_exception` | user node / callback failure published as 3001 (callback: documented divergence from v1 999, contracts.md §J1-5); user message kept; phase `node_execution` with node and call id at the raise line | — |
| `strict_type_mismatch` | 3002; no executed call recorded for the rejected node; phase `node_argument_validation` with node, parameter and type names only | — |
| `publication_failure` | 3005; user code never reached; phase `artifact_publish` at the raiser | — |
| `post_validation_failure` | 4002; `RunReport.iterations` keeps every tile v1 runs, as completed (#685); phase `post_validate` on `meta/metadata.json` | — |
| `fail_fast` | the run stops at the first failing tile; frozen v1 tree / raw / `job.failed` | `invoice` (one tile) |
| `continue_partial` | later tiles still run; `partial`; warning 3001; no `job.failed`; partial sidecar. Callback outside MultiDataTile: v1 has no continue policy, the tests pin that it stays fail_fast | `invoice` (one tile cannot be partial) |
| `all_tiles_failed` | every attempted tile failed; `failed`, not `partial`; `job.failed` with the user's code and message | — |
| `inflight_events` | one `node.invocation_started` / `node.invocation_finished` pair per node call and tile, unique ids, before `node.completed` (#689) | — |

| `success_after_prior_failure` | a successful run after a failed one in the same process: full frozen parity, run-global `seq` restarts, no `job.failed`, no sidecar | — |
| `rerun_no_stale_state` | a same-root rerun after a failure: report, iteration files and sidecar describe the rerun only; `report explain` does not borrow the old sidecar; frozen v1 invoices | — |

The issue's per-pair checklist maps onto the rows as follows: report
iteration counts, `job.failed` and diagnostic phase are asserted in every
failure row; the expected source line and cause in `structured_error`,
`plain_exception` and `publication_failure`; `continue`/`fail_fast` and
partial/all-failed tiles in `fail_fast`, `continue_partial` and
`all_tiles_failed`; stale artifacts in `rerun_no_stale_state`.

## Intentional differences from v1

These are approved v2 contracts, each pinned by a test that measures both
sides against the frozen v1 observation:

- A schema-invalid source invoice is rejected in `pre_validate` with 4001
  before any tile runs; v1 reported a mode-specific symptom, partly after the
  callback ran (contracts.md §I6-0; `TC-UM-*-FLOW/CB-V2/CB-ENTRY-VALERR`).
- An ordinary exception in a v1 callback is published as 3001
  `NodeExecutionFailed`; v1 published 999 with a mode prefix
  (contracts.md §J1-5; `TC-J1-CBP-EV-011`).
- The flow entry's default policy is `continue`; a v1 `Config` seeds
  `fail_fast`, and the callback entry honors `continue` only in
  MultiDataTile, as v1 did (`TC-JREV-F1-005..007`).
- Kept on purpose across a same-root rerun, as v1 kept them: `job.failed`
  (`TC-K3-HYG-002`) and the earlier run's run-scoped logs
  (`TC-K3-HYG-003`). Per-tile `logs/iterations/` files are cleared
  (`TC-K3-HYG-001`).

## CI

`tests/v2/ga/` is part of `tests/`, so it runs wherever the suite runs:

- `.github/workflows/main.yml` (`test`, on pull requests to `main` and
  `develop*`): `tox -e py<ver>-module` for Python 3.10, 3.11, 3.12, 3.13 and
  3.14 — every version in the package classifiers (`requires-python >= 3.10`)
  — on `ubuntu-latest`. A failure fails the job.
- `.github/workflows/v2-ci.yml` (`v2 CI`, on pull requests to `develop/v2`):
  the complete `tests/` suite on Python 3.12, `ubuntu-latest`, with the
  coverage gates.

**Known gap:** the Windows and macOS jobs in `main.yml` (`Test on <os>`) run
the Rust crate tests only; no workflow runs the Python suite, and therefore
this gate, on Windows or macOS. The gate covers Linux only until a workflow
change is approved; this document does not claim platform coverage beyond it.
