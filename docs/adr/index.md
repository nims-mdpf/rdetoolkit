# アーキテクチャ決定記録(ADR)

rdetoolkit v2 の設計を形づくった主要な決定と、その理由の記録です。各 ADR は
「状況(Context)」「決定(Decision)」「帰結(Consequences)」で構成されます。

| ADR | タイトル | 状態 |
|-----|---------|------|
| [ADR-020](0020-eager-execution.md) | Trace 方式を廃止し、eager 実行に転換する | 採用 |
| [ADR-021](0021-conditional-v1-sunset.md) | v1 コードパスの条件ベースのサンセット | ADR-023 に吸収 |
| [ADR-022](0022-call-log-without-lineage.md) | 実行記録をコールログに限定し、値の系譜は追跡しない | 採用 |
| [ADR-023](0023-single-runner-contract-compat.md) | 単一 Runner への統合と契約レベルの v1 互換 | 採用 |

ADR-001〜019 は、v2 の開発初期に検討した「フロー関数をトレースして実行前に DAG を組み立てる」
設計に属する記録です。この設計は ADR-020 で置き換えられ、リリースされた v2 には含まれていないため、
ここには掲載していません。

## v2 の設計原則(要約)

- フローは普通の Python として実行する。トレース・コンパイル・実行前の DAG は持たない(ADR-020)。
- ノードはただの関数。デコレータは登録と呼び出しの記録だけを行う。
- RDE の手続き(モード判定、検証、`job.failed`、ディレクトリ構成)は Runner が所有する(ADR-023)。
- 実行記録は呼び出しの記録であり、データフローを推定しない(ADR-022)。
- 依存性注入はフローの境界で、型注釈だけを根拠に 1 回だけ行う。
- エラーコードは単一のカタログにまとめ、すべてのエラーが対処法を持つ。
- rdetoolkit はワークフローエンジンではない。スケジューリング・ノード並列・再開・キャッシュは提供しない。
