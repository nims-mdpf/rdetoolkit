# ADR-021: v1 コードパスの条件ベースのサンセット

- 状態: ADR-023 に吸収
- 日付: 2026-06

## 状況

v2 の初期計画では、v1 の実装(ワークフローのループ、モード処理、パイプライン)を残したまま、
v2 の Runner を並べて提供する予定でした。この形では、実行経路・設定モデル・戻り値・CLI が
2 系統になり、保守コストが恒久的に 2 倍になります。

## 決定

v1 コードパスの終了を、期限ではなく次の 3 条件で定義する。

1. v2 のテンプレートが公式テンプレートの正として採用される。
2. `migrate apply` が公式 v1 テンプレートの 8 割以上を人手の修正なしで変換できる。
3. v2 が 2 マイナーリリース以上、重大な不具合なしで運用される。

3 条件が成立したら v1 パスを保守モードとし、予告付きで非推奨警告を導入する。

## 帰結

この決定は [ADR-023](0023-single-runner-contract-compat.md) に吸収されました。ADR-023 は、
条件の成立を待って v1 実装を残すのではなく、v1 の**契約**を固定したうえで実装を
v2.0 の正式リリースまでに単一の Runner へ統合する方針に変更しています。

v1 の入口 `run(custom_dataset_function=...)` に非推奨警告を出さないという方針は ADR-023 でも
維持されています。
