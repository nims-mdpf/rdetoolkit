# ADR-022: 実行記録をコールログに限定し、値の系譜は追跡しない

- 状態: 採用
- 日付: 2026-06

## 状況

eager 実行([ADR-020](0020-eager-execution.md))では、実行前に DAG を持たないため、
データフローを示すには実行中に値の同一性を追跡する(どのノードの出力がどのノードの入力に
なったかを推定する)必要があります。検討の結果、次のことが分かりました。

- 研究者が自然に書く pandas のコード(`df.dropna()`、列の演算、コピー)では、出力と入力を
  正確に結び付けられることはほとんどない。出力されるグラフは「データフローに見えるが、
  実際には途切れた推定」になり、利用者に誤った説明を与える。
- 値の同一性表、ガベージコレクションに伴う失効管理、コンテナの走査は、v2 で最も実装リスクの
  高い部分になる。
- 想定する規模では、フロー関数を読めばデータの流れは分かる。

## 決定

v2.0 では値の系譜(lineage)を追跡しない。実行記録は、各ノード呼び出しの
「いつ・何が・どの順で・何回・何ミリ秒かかり・どこで失敗したか・入出力は何型か」を
記録するコールログに限定する。

## 帰結

- 記録は実行順そのものなので、決定的で、推定を含まない。
- `rdetoolkit graph` の出力は呼び出しの順序(Call Sequence)であり、そのことを出力にも明記する。
  データフローの図を名乗らない。
- RunReport、`repro export`、エラーの文脈(どの呼び出しで失敗したか)はコールログだけで成立する。
- 設定モデルには系譜に関する項目を置かない(未知のキーは読み込み時にエラーになる)。
- 系譜の追跡は、需要が実証された場合に限り、既定で無効のオプションとして別の ADR で再検討する。
  その場合も `graph` の既定の出力は呼び出しの順序のままとする。
