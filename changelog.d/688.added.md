A node argument rejected by `execution.type_check: strict` is now attributed
to its node: the 3002 error carries a structured `detail` (node id,
parameter, expected annotation, actual type name, iteration), the failure
diagnostics file records it with phase `node_argument_validation`, and the
event log gets an additive `node.argument_rejected` event. The value itself
is never recorded, and no call is invented for the rejected node: the call
log, `seq` and `call_id` are unchanged. `warn` and `off` behave as before (#688).
