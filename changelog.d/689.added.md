The event log now records node invocations while they run. Right before a
node body starts, an additive `node.invocation_started` event (node id,
iteration, a run-unique `invocation_id`, the enclosing invocation for nested
calls) is written and flushed; when the body returns or raises, a matching
`node.invocation_finished` event names the outcome and the recorded `call_id`.
A process killed inside a long-running node therefore leaves the node it was
running in `events_<run_id>.jsonl`. The existing `node.started` /
`node.completed` / `node.failed` events, the call log, `seq` and `call_id`
are unchanged, and the event schema version stays `"1"` (#689).
