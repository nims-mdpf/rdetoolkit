New `rdetoolkit report explain RUN_REPORT [--format text|json] [--iteration N]
[--full-traceback]` says why a run failed. It shows the lifecycle phase, the
tile and its input, the node and `call_id`, the catalog code, the exception
class, the source `file:line`, the underlying reason and the remediation. It
joins the run report with the failure diagnostics file
`diagnostics_<run_id>.json`, the iteration details and the event log, all
found next to the report by run id. Failed, partial and successful runs are
told apart, and a successful run is not given a cause. A report without a
matching diagnostics file, such as one from an earlier release, still gets an
explanation from the report alone, with a notice that the diagnostics are
unavailable. `--format json` prints the versioned diagnostics envelope
(`command: "report explain"`) and copies no runtime text; `--full-traceback`
adds the recorded frames (file, line, function). `report show`,
`report trace`, `report diagnose` and the run report format are unchanged
(#687).
