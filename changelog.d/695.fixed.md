`execution.type_check` now accepts exactly `off`, `warn` or `strict`
(default `off`). Before, the setting was a free string, so a typo such as
`strcit` or a wrong-case `Strict` loaded silently and was treated like
`strict` at runtime. Any other value — including `null`, a list, a number or
a padded string — is now rejected when the configuration is loaded, through
the existing `ConfigLoadFailed` (1002) error, whose message names
`execution.type_check` and the valid options. This applies to an explicit
`RdeConfig`, discovered `rdeconfig.yaml` / `[tool.rdetoolkit]`, mapping and
`--config` overrides, and `rdetoolkit run REF --validate-only`, which now
fails without calling the flow. Valid values and v1-origin defaults behave
exactly as before (#695).
