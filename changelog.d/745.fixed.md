`rdetoolkit.config` now always means the `rdetoolkit.config` package, whatever
was imported first. Before, the lazy top-level export resolved it to
`rdetoolkit.models.config` until something imported the `rdetoolkit.config`
package, which then replaced it. The top-level stub declares the same package.
The package re-exports `Config`, `SystemSettings`, `MultiDataTileSettings`,
`SmartTableSettings` and `TracebackSettings` from `rdetoolkit.models.config`, so
`rdetoolkit.config.Config` and the other model names still resolve to the same
classes. Code that relies on `rdetoolkit.config is rdetoolkit.models.config`
should import `rdetoolkit.models.config` directly (#745).
