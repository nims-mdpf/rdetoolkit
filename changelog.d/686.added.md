A failed run now writes `logs/diagnostics_<run_id>.json` next to its run
report: a separately versioned document (`schema_version: "1"`, format
`rdetoolkit.failure-diagnostics`) that records, for every failure, the
lifecycle phase (`config_load`, `mode_resolution`, `pre_validate`,
`tile_prepare`, `node_execution`, `node_argument_validation`,
`artifact_publish`, `post_validate`, `finalize`), the published code, the
exception and its `__cause__`/`__context__` chain, the originating source
location, and the tile, node, call and artifact when known. Frames are
file, line and function only; no local variables, argument values or
environment variables are written. The run report schema, `job.failed` and
all error codes are unchanged, and a sidecar that cannot be written never
changes the run's outcome (#686).
