Opt-in `rdetoolkit.testing.rde_case(...)` marker for declarative RDE
integration tests, executed by the new `rde_run` fixture (#691, part of
#682). The marker declares the flow, the project, the expected status
(`success` / `partial` / `failed`), expected artifacts relative to the
isolated data root, and optionally the expected error code and diagnostic
phase. Nothing runs at import or collection time (`pytest --collect-only` has
no side effects); the case runs at fixture setup and a violated expectation
fails the test with an explanation. Misconfigured markers (unknown or
positional parameters, missing project, absolute or `..` expected paths) and
a marked test that does not request `rde_run` are setup errors with a clear
message. The `rde_case` marker is registered by the existing pytest plugin;
it works with `pytest.mark.parametrize` and `pytest.param(..., marks=...)`.
The `node` and `flow` decorators are unchanged.
