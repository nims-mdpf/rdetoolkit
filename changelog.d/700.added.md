New `rdetoolkit repro to-pytest ARCHIVE --ref pkg.mod:callable -o FILE (--project DIR | --stage-inputs DIR) [--expect-status STATUS] [--force]` writes an editable pytest regression test for the run in a full `repro export` archive, as an `rde_case` run by the `rde_run` fixture (#700).

- The flow is never inferred from the archived `flow_id`: `--ref` is required, must consist of Python identifiers, and is imported (not called, no bytecode written) to validate it.
- The archive is checked like `repro inspect`; unsafe member names, a member that differs from `repro_manifest.json`, a `--manifest-only` archive, or a missing run report stop the command with exit 3 and nothing written.
- `--project DIR` references an existing project (for example from `repro import`) whose inputs and effective config must match the archive's SHA-256 digests and `config_digest`. Raw inputs are copied only with the explicit `--stage-inputs DIR`, which extracts the archive with the `repro import` checks.
- The generated test expects `"success"`, the behaviour after the fix; the archived failure becomes the expectation only with an explicit `--expect-status`. The project path is written relative to the test file; only the run id, status, error code and provenance (as comments) are taken from the archive, and environment differences are warned on stderr.
- An existing output is replaced only with `--force`. The source compiles, is `ruff format`-clean and collects under `pytest --collect-only` without running the flow.
