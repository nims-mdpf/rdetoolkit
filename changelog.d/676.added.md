A coding-agent readiness gate now runs the documented agent loop on all five
modes (#676). For each of Invoice, ExcelInvoice, MultiDataTile, RDEFormat and
SmartTable, `tests/v2/acceptance/` builds a project with `new config`,
`new invoice` and `new excelinvoice`. It then runs, in separate processes, the
Skills' exact `nodes lint`, discovery, `doctor`, `run`, `report diagnose` and
`report explain` commands on a failing input, repairs the input and reruns
the same project. It checks the reported tile, call and code, the event log,
each tile's artifacts (metadata units and variable rows included), the JSON
schemas, and the old report's evidence flags after the rerun. A fake secret
that reaches `job.failed` must not appear in any agent-facing JSON. The gate
also checks `continue`/partial exit codes, `run --legacy` parity with the v2
flow, and the migration Skill's worked example. `scripts/agent_readiness_gate.py`
runs it against an installed wheel and a pack installed with its bundled
installer. The `agent-readiness` job of v2 CI is required by the `test`
check, and every leg of the native build matrix runs the same gate.
See `docs/development/agent-readiness-gate.md`.
