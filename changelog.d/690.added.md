`rde_runner` pytest fixture and `rdetoolkit.testing.RdeTestRunner` /
`RdeTestResult` / `RdeIterationSummary` (#690, part of #682).
`rde_runner.run(flow=..., project=..., config=None)` copies the project
(nested `<project>/data` or alias-flat) below the test's `tmp_path` and runs
it through the real Runner exactly like `workflows.run(flow=...)`, so the
source fixture is never modified and every run gets its own root. A failed
run is returned, not raised: the result exposes the `RunReport`, the staged
`project_root` / `data_root`, per-tile summaries, the run report, event log,
diagnostics sidecar (`logs/diagnostics_<run_id>.json`, `None` when absent)
and `job.failed` paths, and `assert_success()` explains a failure with the
catalog codes, messages and artifact locations. Importing
`rdetoolkit.testing` still does not import pytest; `run_flow` is unchanged.
See `docs/usage/testing`.
