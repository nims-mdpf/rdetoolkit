`set_custom_fields` no longer applies an empty or whitespace-only string: the
key keeps its current value in `invoice.custom` (or stays absent), as
`build_meta` omits empty strings. A blank cell read as `""` therefore no longer
fails an `integer` / `number` / `boolean` or date field. The new
`keep_empty_strings=True` restores the previous cast: `""` is stored for a
`string` field without a date format and is a type mismatch otherwise. The
docstring and the migration guides also state that a `string` field without
format keeps non-string values unconverted (#619).
