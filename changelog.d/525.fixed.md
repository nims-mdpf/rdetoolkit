SmartTable runs back the original invoice up to `data/logs/invoice_org.json`
and pass that file as `invoice_org` to flows (`paths.invoice_org`) and to v1
callbacks (`resource_paths.invoice_org`). Before, `invoice_org` was
`data/invoice/invoice.json`, which tile 0 overwrites with its row-merged
invoice, so the original invoice could not be read from any tile processed
after that, and `${invoice:...}` magic variables resolved against tile 0's row.
The backup is kept out of `data/temp`, where SmartTable extracts the uploaded
ZIP, so an archive member named `invoice_org.json` is never overwritten. This
changes the v1 SmartTable contract on purpose: v1.7.1 passed
`data/invoice/invoice.json` and created no backup (#525).
