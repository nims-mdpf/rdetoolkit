RDE artifact assertions and opt-in golden snapshots on `RdeTestResult`
(#692, part of #682): `assert_status`, `assert_error_code`,
`assert_artifact(exists=...)`, `assert_tree`, `assert_json_subset` /
`assert_json_equal` (differences by JSON pointer, strict JSON types),
`assert_csv_columns` / `assert_csv_rows`, `assert_metadata_valid`,
`assert_invoice_valid`, and bounded readers `read_bytes` / `read_text` /
`read_json` / `read_csv` / `iter_csv` (also as functions in
`rdetoolkit.testing.assertions`). Every failure names the artifact, the
difference and the retained data root and run report.
`assert_snapshot(artifact, golden, ...)` compares a file or directory with
approved golden files (JSON by pointer, CSV by cell, text by line diff,
binary by sha256), normalizing only explicitly listed `ignore_fields` /
`ignore_columns` / `ignore_files`. Golden files change only with the new
pytest option `--rde-update-snapshots`, which is refused
when `CI` is set; updated files are listed in the terminal summary. Raw
input directories, symlinks and files above `max_bytes` are refused.
See `docs/usage/testing`.
Approval is flag-only: `assert_snapshot` takes no argument that approves a
change, and golden files, golden directories or any directory inside them
that are symlinks are refused for both comparison and update, so nothing is
ever written through a link.
