The `system.extended_mode` contract is documented and tested: the validated
value is always a `str`; `None` / YAML `null` in mapping input means "not set",
while typed Python code omits the argument (`V2SystemSettings(extended_mode=None)`
stays a type error, and the stub keeps `str`). An unset mode and an explicit
`"invoice"` stay distinct through normalization, `config_digest`, and `repro`
export → import → run (#609).
