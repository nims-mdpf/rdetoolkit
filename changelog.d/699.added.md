`repro export` archives now carry provenance and per-file checksums, and the new `repro inspect ARCHIVE [--format text|json]` reports what an archive records for reproduction without extracting it (#699).

- `repro_manifest.json` moves to `schema_version: "3"` for both archive kinds. A full archive lists every member's `path`, `byte_count` and `sha256`, taken from the bytes written into the zip.
- Both kinds record export-time `provenance`, each attribute with `status` `known`, `unavailable` (with a `reason`) or `not_included`: rdetoolkit, Python and platform versions, the git commit and tracked-file `dirty` state when the project is a git checkout (queried locally; a missing or failing git never fails the export), and the digest of a supported lockfile (`uv.lock`, `poetry.lock`, `pdm.lock`, `Pipfile.lock`, `pylock.toml`). Source code is never archived. No host name, user name, path, remote or branch is recorded.
- `repro import` refuses a member that is missing, unlisted, resized or changed relative to a `"3"` manifest, naming it, before the target appears. `"1"` archives are still imported, with a "provenance unavailable" notice on stderr. The manifest size limit rises from 1 MiB to 64 MiB so that a listing of the maximum member count fits.
- `repro inspect` separates verified inputs, known provenance and unknown or unavailable attributes. `--format json` uses the diagnostics envelope with symbolic findings (`ReproChecksumMismatch`, `ReproProvenanceUnavailable`, `ReproInputsUnverifiable`, `ReproInputsNotIncluded`, `ReproSourceNotIncluded`; `code: null`). It exits 3 on a checksum mismatch and 0 when provenance is only unavailable.
- Matching digests do not make a rerun deterministic: interpreter, dependencies, platform and flow source can still differ.
